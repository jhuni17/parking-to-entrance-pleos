# 주차까지 · 시연 리허설

## 첫 APK의 30초 시연

1. 앱을 연다. 방문지는 코엑스몰 시연 입력이다. 차량 높이 1.85 m, 체류 시간 2시간과 구매 할인 조건을 확인한다.
2. 코엑스 카드에서 높이 제한 2.2 m, 기본 예상 12,000원, 대상 영수증 조건 충족 시 예상 0원을 보여준다.
3. 루프박스 프로필을 켠다. 2.25 m가 표시되고 코엑스는 높이 제한 초과로 내려간다. 대안 A가 위로 올라오며 대안 B에는 높이 정보 확인이 필요하다고 표시된다.
4. 대안 A의 입구 경로 요청을 연다. 취소하면 요청이 없다. 다시 열어 확인하면 “시연 어댑터 요청 처리 · 실제 길안내 시작 아님”을 확인한다. 코엑스몰은 방문 목적지로, 대안 A 입구는 차량 도착점으로 표시된다.

첫 APK의 실제 동작 범위는 카드 판단, 요금 계산, 순서 변경과 시연 어댑터 요청 처리다. 대안과 좌표는 시연값이다. 위 절차는 이후 에뮬레이터 설치 리허설용이며, 이번 변경의 CI 증거는 동일 PR HEAD의 unsigned APK와 JVM 테스트 결과를 확보한 뒤 연결한다.

## 실제 NaviHelper 연동 이후

기본 내비에서 목적지를 선택한 화면, 앱의 목적지 수신, 사용자가 선택한 입구, 기본 내비의 경로 요청 결과를 차례로 기록한다. 문서에 있는 API, 시연용 입력, 런타임 관측을 구분한다. 실제 안내에 사용하는 입구는 공개된 시설 자료에서 확인한 좌표를 사용한다.

## 이번 계약 변경 검증 상태 (2026-11-08)

`ParkingNavigationTest`는 가짜 내비의 연속 목적지 이벤트, 확인 전 요청 0건, 확인의 중복 소비 차단, 거절·예외, 요청 ID가 붙은 동기·지연 입구 되울림과 새 방문지를 검사한다. 시연 어댑터는 실제 내비 수락을 반환하지 않는다. 실패 UI는 “입구 경로 요청 실패”로 분리되어 있으며 현재 화면의 시연 어댑터는 실패를 발생시키지 않는다.

로컬 Gradle 실행은 도구 부재로 실패했다 (`gradle: command not found`; Java 컴파일 도구도 PATH에 없음). 따라서 테스트와 unsigned APK 빌드 통과는 미확인이다. 과거 아티팩트는 이번 변경의 증거가 아니다. Windows 설치·화면 관측과 실제 NaviHelper 콜백은 수행하지 않았으며 별도 승인 후 검증 대상으로 남긴다. 요청 ID를 SDK 이벤트에 연결할 수 있는지도 실제 연동 전 확인해야 한다.
